Decisions that differ from the finding text (and why):

- T-04 asked for identical `contract_sha256` across the three runs; the run contract includes the seed, so the three
  values necessarily differ. Equality is required on `n_params`, `data_identity` minus `seed`, `code.package_sha256`
  and `config` minus `seed`/`run_id`/`metrics`/`summary`; each run's `contract_sha256` is recorded in
  `model.reference_runs`.
- T-03: `spent_before_usd` is compared exactly (it is a declared constant copied into both supervisors, not an
  estimate); only e0 carries the $0.10 tolerance.
- T-11: the explicit C8 window applies to the pre-canary record; the post-canary record passed as
  `--supervision-post` must fall within 20 minutes after the canary end (the script runs it before the replica wait).
- T-18: the committed matrix has `ready: true` with the eager profile, which would derive `FROZEN`; the derivation
  therefore also requires the matrix to be bound to the manifest and to the committed gate file, which the stale
  matrix is not.
- Funding binding keys are `funding_contract_sha256` and `funding_version` (flat `bindings` object, so the on-pod
  check reads `bindings.manifest_sha256` directly).
- `env/pod-overlay-requirements.txt` at this commit listed `pyarrow` once already; only the pytest pin changed.
- `authorize_launch.sh` does not yet call `launch_manifest.py verify` (its many input paths are not among the script's
  arguments); the committed manifest is known to fail `verify` (policy sha) and will be rebuilt before any relaunch.
